# Контейнеризація модулів проєкту за допомогою Docker

## Опис проєкту
Даний проєкт присвячений розробці та контейнеризації багатомодульної системи для повного циклу обробки даних. Архітектура системи побудована на принципах мікросервісів, де кожен етап — від завантаження даних до їхньої візуалізації — виконується в окремому ізольованому Docker-контейнері.

## Мета роботи
Опанування принципів роботи з Docker, створення оптимальних Dockerfile для Python-застосунків, налаштування мережевої взаємодії між контейнерами та оркестрація сервісів за допомогою Docker Compose.

---

## Архітектура та опис сервісів

Проєкт розділений на 6 функціональних блоків:

1.  **data_load**: Відповідає за початковий етап. Зчитує локальний CSV-файл, встановлює з'єднання з базою даних, створює необхідну схему таблиць та виконує масовий імпорт записів.
2.  **data_quality_analysis**: Виконує перевірку цілісності даних. Аналізує набір на наявність пропусків (`null values`), дублікатів та валідує типи даних. Результати перевірки зберігаються у БД.
3.  **data_research**: Проводить статистичний аналіз. Обчислює основні показники: середнє значення, медіану, моду, стандартне відхилення та кореляції.
4.  **visualization**: Отримує агреговані дані з БД та генерує графіки (розподіли, тренди) у форматах PNG або HTML. Файли зберігаються у спільний том.
5.  **web**: Кінцевий сервіс на базі Flask/FastAPI. Забезпечує користувацький інтерфейс для перегляду завантажених даних, результатів аналізу та згенерованих графіків.
6.  **db (PostgreSQL)**: Реляційна база даних, що виступає центральним сховищем для всіх модулів.

---

## Технічна реалізація

### Docker конфігурація
* **Dockerfile**: Для кожного сервісу створено окремий файл на базі образу `python:3.9-slim` для мінімізації розміру кінцевих образів.
* **Docker Compose**: Файл `compose.yaml` описує життєвий цикл усіх сервісів, включаючи порядок їх запуску.
* **Мережі**: Використовується драйвер `bridge` (мережа `project_network`), що дозволяє контейнерам звертатися один до одного за іменами сервісів через внутрішній DNS Docker.
* **Томи (Volumes)**:
    * `db_data`: Для персистентного зберігання даних PostgreSQL між перезапусками.
    * `reports_vol`: Монтується до `/app/reports` у контейнері `visualization` та до `/app/static/reports` у контейнері `web` для обміну файлами.

### Параметри доступу та порти
| Сервіс | Порт (Host) | Порт (Container) | Призначення |
| :--- | :--- | :--- | :--- |
| `web` | 8080 | 5000 | Користувацький інтерфейс |
| `db` | 5432 | 5432 | Сховище даних |

## Інструкція із запуску

Для локального розгортання середовища необхідно виконати наступну послідовність дій:

1.  **Підготовка**: Переконайтеся, що файл `dataset.csv` знаходиться в папці `data/`.
2.  **Збірка та запуск**:
    ```bash
    docker compose up --build
    ```
3.  **Перевірка**: Після завершення логів ініціалізації (появи повідомлення про готовність БД), відкрийте браузер за адресою:
    **http://localhost:8080**
